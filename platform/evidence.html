Platform

Answers point at a version, not at a file

A file changes. A version does not. Every answer records which version it was found in, which is what lets somebody check the work months later when the document has moved on.

Two problems this solves

Both of them show up years later

The document changed

Somebody edits the file after an answer was given. Without version binding, the answer now points at text that is no longer there.

A new read makes a new record

Nothing is edited in place, so the old record and the old answer both survive.

Old answers still open

March's answer still opens March's document, and can still be checked against it.

Nothing is silently corrected

The system does not quietly re-point an old claim at new text that happens to match.

The version expired

Providers age out version history on a schedule set by the plan the firm pays for. Matters outlive that schedule.

The cache is narrow on purpose

It holds a copy of the pages you have already been given answers from, and nothing else. It is not a backup of your document store.

Write once, content addressed

The same page is never stored twice, and what is stored cannot be quietly altered afterwards.

It is never authoritative

Your store remains the system of record. The cache exists to prove what was read, not to tell you what is true now.
