# WYEA design system

Source of truth: the token layer and components in `/styles.css`. Live reference: `/design-system` (noindex, not linked, not in the sitemap), which renders every token and component with a light and dark toggle.

## How to use it

- Pages use components and the spacing utilities (`.mt-4` to `.mt-12`, `.mb-8`) only. A `style` attribute or a `<style>` block fails `npm run build`.
- Components read semantic tokens (`--color-*`, `--text-*`, `--space-*`). Only the semantic layer reads primitives (`--ink-900`, `--oxblood-600` and so on).
- A new color needs a light value, a dark value, a row in the contrast table and a passing `npm run contrast`.
- Breakpoints are 375, 768, 1024 and 1280 px. Media queries use `max-width: 1279px`, `1023px` and `767px` only.
- Header, footer and contact form live in `partials/`. Edit the partial, then run `npm run build`.

### Type

Geist for everything (`--font-display`, `--font-body`), Geist Mono for counts, step numbers, eyebrows and source metadata. Self-hosted, 29 KB. Headings weight 500 with -0.035em tracking. Scale `--text-2xs` 12px to `--text-3xl` 44 to 80px; body `--text-base` 17px.

### Space, radius, shadow, motion

4px spacing scale (`--space-1` to `--space-36`). Radii `--radius-sm` 12, `--radius-md` 16, `--radius-lg` 22, `--radius-xl` 28, `--radius-pill`. Shadows: `--shadow-card` on the product card only, `--shadow-soft` on mini snippets. Motion: fade-in on scroll only, zero under prefers-reduced-motion; no carousels or looping motion.

## Components

Each note says when to use it, what it needs and what never goes in it.

### Navigation (`partials/header.html`)
Every page. Insurers and Platform open menus; Security, How we work and About are links; Book a demo is the one button. Never add a sixth top-level entry without removing one. Never link a noindex page.

### Hero (`.hero`, `.hero-center`, `.hero-sub`)
The homepage uses `.hero-center`: a headline of about 5 words, one short lede, Book a demo and See how it works.

The first block of every page. Needs an eyebrow, one h1 carrying the category words, one subhead sentence and two actions: Book a demo, then See how it works. Interior pages add `.hero-sub` and a breadcrumb. Never a second h1, never a statistic.

### Source-answer card (`.app` + `.ans`)
Home and /insurance, under the hero. Needs the question in the bar, the read and matched counts, three found rows with a quoted passage and its source line, one flagged row for a document that could not be read, and the `.tag-invented` label beside the caption. Every name, clause and date is invented. Never internal vocabulary: no hashes, offsets, version ids or connector names.

### Principals band (`.people`, `.person-photo`, `.principals-head`)
Home, /insurance and /about. Needs both principals with photo, name, role and one-line credential. It stands where a logo wall would. Never a customer logo, quote or metric.

### Trust pillars (`.pillars`)
Home and /security. Exactly four: every line opens its source; answers keep their version; one system per insurer; a reviewer signs off. Each needs one or two sentences and a link to the page that backs it. Never a certification claim.

### Process timeline (`.timeline`)
Home and /how-we-work. Six steps in order: call, NDA, one-week prototype, fixed-price scope, build, support. Mark the prototype step `.is-key`. Never a date promise beyond the one week.

### Stat band (`.stats`, `.stat`, `cite`)
Segment pages and /insurance. Each stat needs a number, one sentence and a `cite` with a link to a source page that opens. Never a customer metric, never an unsourced figure. Commitments (one week, two engineers) go in a rule list, not here.

### Rule list (`.rulelist`)
Spec sheets and commitments: label left, value right. Add `.rulelist-1` for one column.

### Vendor-review table (`.dtable`)
/security/vendor-review. Columns: requirement, source, WYEA today, status. The status is a pill: `.pill-ok` for publish as stated, `.pill-ask` for Ask us, `.pill-flag` for not held. Rendered from docs/brief/vendor-review.md exactly. Every `td` carries `data-label` so the phone layout can name its column.

### Not-held list (`.notheld`)
/security and /security/vendor-review. Each item is something a reviewer may ask for that WYEA does not have, with one sentence and a "Not held" pill. Never softened, never removed without the thing existing.

### Comparison table (`.dtable` + `.is-ours`)
/compare. Row headers are the questions a buyer asks; columns are a shared product and a firm-owned engine. Mark WYEA's column `.is-ours`. Must include the rows where the shared product is the better fit.

### FAQ (`.faq`)
Most pages. Native `<details>`; the answer is in the HTML. One question per entry, answered in the first sentence. When the page carries FAQPage JSON-LD, the two must match word for word.

### Call to action band (`.cta-band`)
Every page, last before the footer. Needs a heading, one sentence, the booking button and the contact form partial. The booking link never changes.

### Article layout (`.article-meta`, `.prose`, `.sources`)
Guides and research. Needs byline WYEA, published and updated dates in `<time>`, and a numbered sources list. A draft carries `.draft-banner` and noindex.

### Footer (`partials/footer.html`)
Every page. WYEA LLC, Newport Beach, California. Four link columns.

### Supporting components
- `.tile`: an entry in a ruled grid (`.grid-2`, `.grid-3`, `.grid-4`).
- `.explorer`: a ruled accordion with a figure beside it.
- `.vprop`: a parent claim with three named parts.
- `.feature`: prose beside a figure, alternating.
- `.ticks`: a short ruled list inside another component.
- `.explore`: related links at the foot of a page.
- `.callout`: a quoted source inside prose.
- `.pill`, `.tag-invented`: status marks.
- `.btn-primary`, `.btn-ghost`, `.btn-light`, `.btn-outline-light`, `.arrow`: actions. One primary button per view.
